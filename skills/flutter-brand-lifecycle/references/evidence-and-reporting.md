# 证据与报告

## 状态定义

| 状态 | 含义 |
| --- | --- |
| `COMPLETE` | 适用要求已满足，并有足以证明该层结论的当前证据 |
| `INCOMPLETE` | 已确认适用，但实现、配置或行为存在缺项或错误 |
| `NOT_VERIFIED` | 可能已实现，但当前没有足够证据判断 |
| `BLOCKED` | 已知外部资料、权限、环境或依赖阻止完成或验证 |
| `NOT_APPLICABLE` | 有证据证明该项目或品牌不需要此项 |
| `REQUIRES_PRODUCT_DECISION` | 实现选择会改变产品语义，当前事实不能确定意图 |

不要用 `NOT_APPLICABLE` 代替缺失，不要用 `BLOCKED` 代替尚未尝试的验证。

## 证据层级

按结论需要选择证据：

1. **规格与决定**：证明产品身份、能力、非目标、失败和验收语义。
2. **代码与配置**：证明当前实现、调用链和平台声明。
3. **静态校验与测试**：证明特定不变量和错误场景。
4. **构建与产物检查**：证明特定目标能够构建，以及产物身份、资源和签名实际值。
5. **真实集成**：证明后台、厂商平台、域名或服务在指定环境工作。
6. **真机与发布链路**：证明设备行为、上传、分发、升级和恢复路径。

较高层证据不自动覆盖未测试的平台、环境、渠道或业务路径。历史记录若没有在当前分支和环境复核，应说明可能已经变化。

## 检查项结构

每个检查项记录：

```text
检查项：
适用性：APPLICABLE / NOT_APPLICABLE / UNKNOWN
不变量或验收条件：
状态：
证据：
证据边界：
缺口或阻塞：
下一步：
```

核心领域通常包括品牌模型、事实来源、目标选择、配置资源、适用平台、开发构建入口、产物和回归。条件领域来自项目发现。

## 四层完成度

### 配置完整

品牌身份、品牌数据、资源、环境和适用目标登记完整、一致且可追溯。配置文件存在但包含占位值、复制凭据或未知归属时不完整。

### 代码完整

Flutter、适用平台、开发入口和构建链已按项目契约接入；生成、静态校验、测试及必要反向场景通过。只存在代码但未运行适用验证时为 `NOT_VERIFIED`。

### 集成完整

适用后端品牌标识、外部服务、域名和真实环境交互有当前证据。没有条件能力的项目可以在这些能力均有 `NOT_APPLICABLE` 证据时达到集成完整。

### 发布就绪

适用平台的正式身份、签名、最终产物、安装运行、上传分发和升级/恢复路径达到项目验收条件。Debug、模拟器、Mock 或测试账号证据不能代替规格要求的正式链路。

## 聚合规则

- 某层全部适用项为 `COMPLETE`，且不适用项都有证据：该层 `COMPLETE`。
- 任一适用项为 `INCOMPLETE`：该层 `INCOMPLETE`。
- 没有已知错误但存在必要 `NOT_VERIFIED`：该层 `NOT_VERIFIED`。
- 存在阻止完成的必要依赖：报告该层当前状态，并单列 `BLOCKED` 项。
- 存在未决产品语义：单列 `REQUIRES_PRODUCT_DECISION`，不得自行选择实现。
- 不使用无定义权重的百分比代替状态和证据。

## 标准报告

```text
操作：add / edit / deactivate / remove / audit
目标品牌：
品牌模式：
当前品牌集合：
支持平台：
适用条件能力：

总体结论：
- 配置完整：
- 代码完整：
- 集成完整：
- 发布就绪：

已完成：
- 检查项、证据及证据边界

未完成：
- 检查项、实际缺口和影响

未验证：
- 检查项、已有线索和需要的验证

不适用：
- 检查项和判定证据

阻塞：
- 检查项、阻塞条件和恢复条件

需要产品决策：
- 待决定语义及不同选择的影响

实际执行的验证：
- 命令或操作、结果和覆盖范围

下一步：
1. 最短可执行动作
```

报告可省略空分组，但四层结论和实际验证边界必须保留。若用户要求实施，报告应描述最终变更和验证，而不是重复过程日志。
