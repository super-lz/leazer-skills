# Flutter 品牌生命周期

## 目标

根据当前项目的真实规格和实现指导品牌生命周期工作，并用证据判断结果处于配置完整、代码完整、集成完整或发布就绪中的哪一层。

严格约束品牌一致性、隔离、凭据、安全失败、回归和证据。动态发现品牌数量、目录、平台、目标机制、条件能力、构建系统和验证入口。

## 事实来源

进入项目后按作用域读取事实，不把本 Skill 当作项目配置事实源：

1. 读取适用的 `AGENTS.md`、项目规范和贡献规则。
2. 读取品牌或产品主规格，确认用户结果、能力边界、失败行为和验收条件。
3. 读取当前代码、配置和测试，确认现有实现。
4. 需要解释演进或删除影响时再检查 Git 历史和发布资料。

项目已有稳定品牌机制时，沿现有机制扩展。除非用户明确要求架构迁移，不另建一套品牌系统，也不把某个项目的实现方式推广为所有 Flutter 项目的标准。

## 操作模式

根据请求选择模式；一次任务可以先 `audit` 再进入其他模式：

- `add`：新增品牌并保护已有品牌。
- `edit`：修改现有品牌，按变化语义确定影响范围。
- `deactivate`：停止入口、构建或发布，同时保留所需历史兼容。
- `remove`：审计线上、升级和外部依赖后物理删除品牌。
- `audit`：只读检查当前品牌实现和接入完整度。

## 工作流程

1. 确认仓库、分支、工作区状态和本次目标；保留无关改动。
2. 从项目事实源识别品牌模式、当前品牌集合、支持平台、构建入口和条件能力。按 [项目发现](references/project-discovery.md) 执行。
3. 输出已确认事实、适用范围、缺失输入及必须由产品决定的语义。先调查，只询问无法从项目确认且会影响正确性的内容。
4. 依据 [核心不变量](references/core-invariants.md) 检查计划。发现冲突时先解决冲突，不用复制旧品牌、静默回退或删除校验掩盖缺项。
5. 按 [生命周期操作](references/lifecycle-operations.md) 指导或实施最小完整变更。用户已要求实施时继续完成授权范围内的修改和验证，不停在清单或建议。
6. 运行项目已有的生成、格式化、静态校验、测试和适用构建。命令、平台和产物来自当前项目，不从本 Skill 猜测。
7. 按 [证据与报告](references/evidence-and-reporting.md) 评估每项适用性和状态，输出分层结论、证据、缺口和下一步。

## 适用性优先

先判断能力是否适用，再检查完整性。地图、推送、Deep Link、支付、分析、分享、WebView、OTA、商店发布和各原生平台都是条件项。

- 产品明确不需要，且没有可达实现：`NOT_APPLICABLE`。
- 当前品牌明确关闭，关闭路径和失败行为完整：可标记 `NOT_APPLICABLE`，同时给出证据。
- 能力可达但配置缺失：`INCOMPLETE`。
- 所需外部资料或权限未提供：`BLOCKED`。
- 无法证明需要或不需要：`NOT_VERIFIED` 或 `REQUIRES_PRODUCT_DECISION`。

不能仅凭密钥或目录不存在判定不适用；缺失也可能表示接入未完成。

## 实施原则

- 品牌 manifest、Dart define、flavor、Scheme、product、远端配置都只是可能的机制。先识别项目实际模型，再沿调用链检查逻辑目标如何传播到平台构建和最终产物。
- 项目使用品牌 manifest 加平台 flavor 时，manifest 管理的 Flutter 语义与原生身份分别由各自事实源维护，并通过校验保证目标一致；不要默认用 manifest 覆盖包身份、签名或平台能力。
- 修改文案、资源、能力、包身份、Deep Link 或发布配置时，按实际传播范围验证，不要求无关能力重复验收。
- 新增品牌必须验证新品牌并回归已有品牌。删除品牌必须先区分停用与物理删除。
- 正式凭据通过项目规定的受控渠道提供。Skill 输出只记录槽位、状态和验证结果，不记录秘密值。

## 完成判定

统一使用以下状态：

- `COMPLETE`
- `INCOMPLETE`
- `NOT_VERIFIED`
- `BLOCKED`
- `NOT_APPLICABLE`
- `REQUIRES_PRODUCT_DECISION`

分别判断配置完整、代码完整、集成完整和发布就绪。只有某一层全部适用检查均为 `COMPLETE` 时，才能判定该层完成。静态检查、Mock、配置文件存在或工具调用成功不能单独证明真实服务、真机或发布链路完成。

## 交付格式

交付至少包含：

1. 操作、目标品牌、品牌模式、支持平台和已发现条件能力。
2. 四层完成状态。
3. 已完成、未完成、未验证、不适用、阻塞及待产品决策项。
4. 每个结论的证据及其能证明的边界。
5. 已实际运行的验证、未运行原因和最短下一步。

不使用没有证据支撑的完成百分比。没有安全或必要变更时，明确报告已验证无需修改。
