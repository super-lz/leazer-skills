# 项目实现规格

本文件是当前项目的主实现规格。它承接产品目标和已确认的实现决策，细化到系统行为、边界、流程、失败处理和验收标准。

主实现规格是项目骨骼：即使脱离当前代码，也应能据此重建一个业务语义等价的系统。代码是项目皮肤和血肉：真实实现机制、当前可观察行为和可追溯代码事实以代码为准。当稳定代码现实已经存在而本文件落后时，应按 `docs/spec/AGENTS.md` 的回写规则更新本文件。

## 目标

说明项目要解决的核心问题和用户可感知的结果。目标必须先回答：

- 真实用户是谁。
- 用户当前遇到的真实问题是什么。
- 项目完成后，用户能得到什么可感知结果。
- 哪些信号能证明这个结果已经达成。

## 背景

说明必要上下文、运行环境、现有系统事实和关键约束。只记录会影响实现判断的事实。

## 原则

- 用第一性原理确认真实约束，再决定实现。
- 以最终目的为依据组织功能，不为了技术偏好、临时想法或功能堆叠扩大范围。
- 非必要不增加组件、状态、文档和流程。
- 代码实现必须能回到本规格中的目标、规则、边界或验收点。
- 本规格必须完整描述目标、业务语义、流程、边界、状态变化、失败处理和关键不变量；不记录语言、框架、组件拆分和事件机制等普通实现细节。
- 如果某个功能、流程、组件、接口或验收点无法说明服务哪个真实用户需求，应从本规格中删除或移入开放问题等待确认。
- 本规格追求正确指引和宽松规范：说明稳定目的、边界和关键约束，给实现保留选择更优代码结构的空间。
