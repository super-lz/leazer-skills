# 文档区入口

本目录保存项目长期文档。进入 `docs/` 下执行任务时，先读本文件，再根据任务需要读取子目录入口。

## 目录分类

- `spec/`：实现规格。这里的文档是代码实现、测试和验收的主要依据。
- `appendix/`：附录辅助材料。这里的文档面向人类快速理解，可以是流程图、草图或临时辅助说明，不作为实现依据。

## 文档治理

- 不把开发过程、临时计划、每日进度写入长期文档。
- AI 对话只用于形成当次决策，不作为长期依据；稳定决策必须进入实现规格或代码，真实变动必须能从 Git 历史追溯。
- 不新增长期技术文档来重复代码实现；代码、类型、测试和必要注释承担主要技术说明。
- 不新增与最终目的无关的长期文档；每份长期文档都必须说明它服务的真实需求、稳定决策或必要证据。
- 只有复杂技术调研需要保留证据时，才新增短文档；调研结论必须回到实现规格或代码。
- 新文档优先放入现有分类。只有分类语义不够用时，才新增目录，并补对应入口说明。
